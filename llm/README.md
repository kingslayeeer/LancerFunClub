# Локальная LLM — модуль генерации (участник 4)

Что лежит в папке:

| Файл | Зачем |
|---|---|
| `llm_module/generator.py` | Модуль генерации: единый интерфейс `LLMGenerator.generate(...)` для бэкенда |
| `llm_module/config.py` | Настройки: модель, адрес сервера, таймауты, параметры генерации (пресеты) |
| `check_model.py` | Быстрая проверка «модель запущена и отвечает» |
| `benchmark.py` | Сравнение 2–3 моделей: скорость, память, автометрики текста, ответы для ручной оценки |
| `test_queries.jsonl` | 10 тестовых запросов (временные, пока нет датасета участника 3) |
| `tests/` | Тесты модуля без настоящей модели |
| `MODELS.md` | Сравнительная таблица моделей и обоснование выбора (для презентации) |

## 1. Установка и запуск модели (Ollama)

1. Скачать и установить Ollama: https://ollama.com/download (Windows / macOS / Linux).
   После установки сервер работает в фоне на `http://localhost:11434`.
2. Скачать модели для сравнения (каждая весит 3–8 ГБ):
   ```bash
   ollama pull qwen3:8b          # основной кандидат
   ollama pull gemma3:12b        # если есть 12+ ГБ видеопамяти или 16+ ГБ ОЗУ
   ollama pull gemma3:4b         # лёгкий вариант для слабых ноутбуков
   ```
   Российские модели берутся с Hugging Face в формате GGUF
   (точное имя репозитория и квантизации проверить на huggingface.co перед запуском):
   ```bash
   ollama pull hf.co/t-tech/T-lite-it-2.1-GGUF:Q4_K_M
   ollama pull hf.co/yandex/YandexGPT-5-Lite-8B-instruct-GGUF:Q4_K_M
   ```
3. Проверить вручную: `ollama run qwen3:8b "Напиши письмо о переносе встречи"`
4. Установить зависимости Python и проверить модуль:
   ```bash
   pip install requests pytest
   python check_model.py qwen3:8b
   ```

### Запасной вариант: llama.cpp / vLLM
Модуль умеет работать с любым OpenAI-совместимым сервером:
```bash
# llama.cpp
llama-server -m model-Q4_K_M.gguf --port 8080 -c 8192
# затем
LLM_BACKEND=openai LLM_BASE_URL=http://localhost:8080 python check_model.py
```
vLLM имеет смысл только при видеокарте NVIDIA с 16+ ГБ; для MVP достаточно Ollama.

## 2. Квантизация: что выбрать под железо

Квантизация — сжатие весов модели. Чем меньше бит, тем меньше памяти и быстрее, но чуть хуже текст.

| Квантизация | Память для модели 8B (с контекстом 8K) | Качество | Когда брать |
|---|---|---|---|
| Q4_K_M | ≈ 6 ГБ | хорошее, потери малы | **по умолчанию**; ноутбуки, видеокарты 8 ГБ |
| Q5_K_M | ≈ 7 ГБ | почти как оригинал | видеокарта 10–12 ГБ или 16 ГБ ОЗУ |
| Q8_0 | ≈ 10 ГБ | практически без потерь | видеокарта 12+ ГБ |

Ориентиры (примерно): на видеокарте 8B‑модель в Q4 выдаёт 30–80 токенов/с — письмо за 5–15 секунд;
на одном процессоре 5–15 токенов/с — письмо за 30–90 секунд. Точные цифры — из `benchmark.py` на вашем железе.

В Ollama по умолчанию скачивается Q4_K_M. Другую квантизацию выбирают тегом, например
`ollama pull qwen3:8b-q8_0` (список тегов — на странице модели в ollama.com/library).

## 3. Параметры генерации (`config.py`)

| Параметр | Значение | Почему |
|---|---|---|
| temperature | 0.4 (создание), 0.2 (редактирование), 0.0 (извлечение параметров) | деловой текст должен быть предсказуемым |
| top_p | 0.9 | отсекает совсем маловероятные слова |
| repeat_penalty | 1.1 | малые модели склонны повторять фразы |
| max_tokens | 1024 (≈ 1–1,5 страницы), 400 для «кратко» | ограничивает длину и время ответа |
| num_ctx | 8192 | хватает на промпт + черновик + ответ |
| think | false | у Qwen3 отключаем «рассуждения» — они не нужны и замедляют ответ в 2–3 раза |

Все параметры можно менять через переменные окружения: `LLM_MODEL`, `LLM_BACKEND`, `LLM_BASE_URL`,
`LLM_TIMEOUT`, `LLM_RETRIES`.

## 4. Как пользоваться модулем (для бэкенда, участник 6)

```python
from llm_module import LLMGenerator, LLMError, LLMTimeoutError, LLMUnavailableError

llm = LLMGenerator()   # модель и адрес из config.py / переменных окружения

try:
    result = llm.generate(
        prompt=filled_prompt,          # промпт из базы с подставленными данными
        system=system_prompt,          # роль модели (необязательно)
        preset="document",             # "document" | "edit" | "short" | "classify"
    )
except LLMUnavailableError:
    ...  # модель не запущена / не скачана → 503
except LLMTimeoutError:
    ...  # слишком долго → 504
except LLMError:
    ...  # прочие ошибки → 502

result.text              # готовый текст
result.seconds           # время ответа
result.output_tokens     # сколько токенов сгенерировано
result.tokens_per_second
```

Для участника 5 (извлечение параметров в JSON) — пресет `classify`, температура 0.

### Генерация по базе промптов (`prompts/`)

Модуль сам читает `prompts/data/prompts.json` и `prompts/editor.json`, подставляет поля
в `user_template`, добавляет few-shot примеры и вызывает модель:

```python
from llm.llm_module import load_prompts, generate_document, edit_text

prompts = load_prompts()                               # {id: промпт}
entry = prompts["letter_official_finance_standard"]    # id выбирает модуль участника 5

result = generate_document(entry, {
    "topic": "о просрочке оплаты",
    "recipient": "Иванов И. И., генеральный директор",
    "body": "просрочена оплата по договору поставки",   # обязательное поле
    "deadline": "5 рабочих дней",
})
print(result.text)

# POST /edit
result = edit_text(user_text, style="official", length="standard")
```

Вместо незаполненных полей подставляется плейсхолдер (`[НОМЕР ДОГОВОРА]`, `[СУММА]` и т.д.),
модель оставляет его в тексте, и пользователь дописывает сам — так модель не выдумывает данные.
Для объёма `short` / `long` длина ответа подбирается автоматически.

Проверка перед запуском API: `llm.is_available()` → `True/False` (удобно для `/health`).

### Docker (для участников 6 и 7)
Ollama есть в виде готового образа `ollama/ollama`. В `docker-compose.yml` бэкенду достаточно передать
`LLM_BASE_URL=http://ollama:11434`. Модели для офлайн-сборки хранятся в томе `/root/.ollama`.

## 5. Бенчмарк

```bash
python benchmark.py --models qwen3:8b gemma3:12b hf.co/t-tech/T-lite-it-2.1-GGUF:Q4_K_M
```
Результаты в папке `results/`:
- `summary.md` — сводная таблица (время, скорость, память, автометрики) → вставить в `MODELS.md`;
- `answers.csv` — все ответы; открыть в Excel и заполнить колонку «оценка_1_5»
  (ясность цели, соответствие стилю, грамотность). Лучше, чтобы оценивали 2–3 человека из команды.

Когда участник 3 подготовит свой датасет, его нужно сохранить в том же формате, что `test_queries.jsonl`.

## 6. Тесты
```bash
python -m pytest tests -q
```
Тесты не требуют настоящей модели: поднимают фейковый сервер и проверяют обработку ошибок, таймаутов, пресетов.
