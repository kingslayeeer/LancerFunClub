# Business Documents Prompts

База промптов для генератора деловых документов на локальной LLM (T-lite-it-2.1 8B / Qwen3-8B).

Проектный практикум · Участник 2 (промпт-инженер)

---

## 1. Что это

Библиотека промптов, которая заставляет локальную модель писать деловые документы по параметрам: **форма × стиль × сфера × объём**. Плюс промпт-редактор для вычистки готового текста.

## 5. Формат промпта

```json
{
  "id": "letter_official_finance_standard",
  "version": "1.0",
  "meta": {
    "form": "letter",
    "style": "official",
    "sphere": "finance",
    "length": "standard",
    "description": "...",
    "tags": ["..."],
    "few_shot_count": 1,
    "model_hint": "qwen3-8b",
    "use_when": "..."
  },
  "prompt": {
    "system": "...",
    "user_template": "...",
    "few_shot": [{"user": "...", "assistant": "...", "note": "..."}]
  },
  "constraints": {
    "must": ["..."],
    "must_not": ["..."],
    "forbidden_words": ["..."]
  },
  "output_format": {
    "type": "plain_text",
    "placeholders": ["[ДОЛЖНОСТЬ]", "[ФИО]"],
    "no_preamble": true,
    "no_thinking": true
  }
}
```

**ID** = `{form}_{style}_{sphere}_{length}`

Пример: `letter_official_finance_standard` = письмо + официальный + финансы + стандартный.

Для универсальных (без отрасли) — сфера `general`: `letter_neutral_general_short`.

## 7. Критично для Qwen3

Во всех system-промптах обязательна строка:

> Не показывай рассуждения. Не используй теги thinking. Выведи только готовый документ.

Иначе модель вставит цепочку размышлений в вывод.

## 8. Как писать промпт (кратко)

| Блок ↕▾ | Размер ↕▾ | Что внутри ↕▾ |
|---|---|---|
| −`system` | 40–80 токенов | роль + язык + стиль + Qwen3-обвязка |
| `user_template` | 80–150 токенов | задача + плейсхолдеры + структура + объём + 3–5 запрещённых слов |
| `few_shot` | 1–3 примера | полный пример с синтетическими данными |
| `constraints` | — | `must` / `must_not` / `forbidden_words` |
| `output_format` | — | `plain_text` + `placeholders` + `no_thinking` |
⚙

**Правила для малых моделей:**

- Императив, не описание: «Пиши кратко» ✅, «должно быть кратко» ❌
- Позитивные инструкции: «используй глаголы: сообщаем, просим» ✅
- Конкретика: «120–280 слов» ✅, «средний объём» ❌
- Few-shot важнее инструкций: правило соблюдено в примере > абзац правил
- В few-shot **не должно быть** запрещённых слов из `forbidden_words` — модель скопирует пример, а не инструкцию

Итого **300–600 токенов** на промпт — оптимум для 8B.

## 9. Три стиля (кратко)

### Официально-деловой

- Обращение: «Уважаемый Иван Иванович!»
- «Вы» с заглавной, «наша организация» вместо «мы»
- Глаголы: уведомляю, прошу, приказываю, направляю
- Допустимы формулы: «Настоящим уведомляю», «На основании п. …»
- Когда: приказы, заявления, ответы на претензии, юр. документы

### Нейтрально-деловой

- Обращение: «Иван Иванович, добрый день!»
- «вы»/«мы» строчными
- Глаголы: сообщаем, предлагаем, уточняем, подтверждаем
- Запрещено: «Настоящим довожу до вашего сведения», «В целях…»
- Когда: рабочие письма, записки, отчёты, КП

### Дружелюбно-деловой

- Обращение: «Иван Иванович, добрый день!»
- «коллеги», «команда»
- Глаголы: давайте, предлагаю, подскажите, будет здорово, если…
- Запрещено: панибратство, сленг, эмодзи
- Когда: внутренняя переписка, клиентский сервис

> ⚠️ Официальный стиль ≠ канцелярит. Формулы в `official_allowed` — это жанр, их не трогаем в `official`. В `neutral`/`friendly` — заменяем. Список — в `stop_words.json`.

## 12. Конфиденциальность

Все примеры в промптах **синтетические**: без реальных ФИО, реквизитов и адресов. Требование Участника 7 (защита данных).

## 13. Известные ограничения

- **Промптов 15, не 40** — покрывают все формы, но не все сферы (`education`, `gov` пусты).
- **Few-shot по 1 примеру** — для MVP достаточно, но при тестировании может понадобиться 2 для сложных форм.
- **Нет автоматической валидации** — проверено вручную, скрипт `validate_prompts.py` ещё не написан.
- **Не протестировано на модели** — промпты написаны, но прогон на T-lite-it ещё предстоит.
